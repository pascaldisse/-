# 虚菌基盤評価 — Gray–Scott を菌糸の「地」とし、信号を偽造しない

調査基準：AJ Smith `canalisation`、共有 clone の基準枝 `f92bfb3`；
`https://ajsmithhq.com/` の view-source（2026-08-07 取得）；Gaia の
`docs/01-roadmap.md`、`docs/02-evidence-ledger.md`。以下で **原典事実** と
**愛無への提案** を混ぜない。

## 判定

**採る。ただし Gray–Scott を「菌の電圧発生器」と呼ばない。**

これは低コストで、生き物らしい局所の濃淡・分岐・消長をつくる substrate にはなる。
しかし Gray–Scott の `U,V∈[0,1]`、数値 step、画像上の colony は無次元の計算状態であり、
実測された fungal spike の mV・h・min ではない。電圧値へ直結すれば、絵のパターンを
生体計測と取り違える。虚菌では次の三層を分ける。

```text
場 G              Gray–Scott：局所の可用性／興奮性／履歴の地形
輸送 A            auxin-like 有向 graph：経路・容量・記憶
声 E              1 Hz event/waveform：mV と h/min 封筒を守る観測可能な出力

刺激・環境 W ─→ G ─→ A ─→ E ─→ view / log / actuator
実測 1 Hz R ───────────→ calibration / comparison（G,E を上書きしない）
```

`G` は形、`A` は関係、`E` は測定窓である。この分離なら、実測が増えたときは
`E` の較正・比較を更新でき、視覚の気持ちよさが evidence を侵食しない。

## 1. 観察した Gray–Scott 場：使える所、借りてはいけない所

ajsmithhq.com はページ全長を一枚の WebGL2 plate として計算する。状態は
`(U,V,N)`、式は

```text
dU/dt = Du ∇²U − U V² + F(1−U)
dV/dt = Dv ∇²V + U V² − (F+k)V
```

である。実装値は `Du=.42, Dv=.21, dt=1`、8近傍 stencil、`F,k` は params texture
から読む。通常地は `F=.0300, k=.0688`、各 colony は DOM の位置から円形 plateau と
滑らかな勾配をつくり、その内側だけ別の `F,k` を与える。`N` は筆／drag が注入する
一時 nutrient であり、`k` を最大 `.0105` 下げ、各 step `.99985` 倍で消える。従って
field の規則は一つ、境界ごとの絵規則ではない。

解像度は viewport/document から `150..420 × 64..2600` cell、総数は最大 470,000。
通常は目標 700 steps/s（frame ごと 4..36 step）、reduced-motion 時は 26,000 step
まで成熟させる。float state は手製 bilinear で表示し、32×32 reduce pass が
`V>.18` の被覆率を読む。WebGL2 と float render target が無い時は、動かぬ readout を
残さず plate 不在を明示する。これは virtual substrate に移すべき誠実な失敗様式である。

**借りるもの**：同一 equation、局所 parameter map、外因の brush/source、GPU
ping-pong、状態から直接読む instrument view、capability failure の明示。

**借りないもの**：DOM 位置を colony の真因にすること、screen pixel と生物距離の混同、
`V` を volt と呼ぶこと、wall-clock の 700 SPS を菌の生理時刻と呼ぶこと。元実装の
`Math.random()` は再演不能でもあるため、虚菌では seed を状態／log に必ず残す。

## 2. 実測封筒を、出力の契約として載せる

Gaia evidence A1/A2 は、fungal electrical activity を **0.03–2.1 mV**、spike duration
**1–21 h**、平均 inter-spike interval **約 41–116 min** と報告する。oyster は二群
**約 .88 mV（高頻度）／1.3 mV（低頻度）**。読む器は differential 24-bit、電極間
1–2 cm、**約 1 Hz** 採取で足りる。これは「意味」や「言語」の証拠ではない（A8）。

よって `E` を次の契約で実装する。

| 項 | 実装 | 守る境界 |
|---|---|---|
| clock | `tick=1 s`、全入力・全出力を UTC monotonic sequence として記録 | 観測と model を同じ 1 Hz 格子へ置く。GPU step は内部 substep であって生理秒ではない。 |
| field feature | 各 probe の `V, |∇V|, ΔV, N, local coverage` と、A の flux/capacity を 1 Hz sample | 生の pixel 色を mV にしない。feature schema/version を log。 |
| event hazard | feature の加重＋閾値越えの **rate** から、再生可能 seed で onset 候補を出す。refractory は種／channel 別 | burst を frame-rate 依存にせず、41–116 min の間隔分布を acceptance gate にする。 |
| waveform | onset 後は rise/plateau/recovery を時刻で進め、duration を 1–21 h 内から選ぶ。amplitude は clamp した `.03–2.1 mV` | `E_mV` は simulation-proxy。実菌を「再生」したとの主張を禁ずる。 |
| oyster profile | `oyster-H` と `oyster-L` を明示的 mixture にし、中心 .88 / 1.3 mV、各々の rate/duration は測定データを得るまで仮値帳簿 | 二つの値を全菌種の二峰性、又は high/low の因果へ昇格させない。 |
| observed path | ADC 1 Hz 値は生値、校正、artifact flag、channel metadata と共に別 stream 保存。model への同化は opt-in | 読み値を見栄えのために G へ直接注入しない。read と write を分離。 |

最初の acceptance は「正しそうな波形」ではない：一時間以上の replay で、1 Hz CSV が
時間順に単調、振幅 clamp 違反ゼロ、duration/ISI の分位が設定 envelope 内、seed 固定で
同じ event 列、view 切替で state digest 不変、である。実測と比べる段階では種・培地・
電極配置を揃えた session ごとに、振幅・duration・ISI の分布距離を出す。合わなければ
係数を美化せず **UNVERIFIED** と記す。

## 3. auxin/canalisation を上に置く場所

`canalisation/src/10_auxin.js` は、頂点濃度 `a`、細胞 PIN 総量 `p`、有向辺の PIN 記憶
`pi`・配分 `P`・流束 `J` を持つ graph solver である。低 auxin では高濃度隣接へ向く
`grad`、高 auxin では流束記憶へ向く `flux` を sigmoid で混ぜる；流束の正部分の二乗が
`pi` を強める。葉脈はこの有向記憶で初めて「経路」になる。Gray–Scott 単独には向きも
長期 edge memory もない。

提案は、`G` の local maxima/ridge と低い `k_eff` の連結を候補点とし、固定格子又は
sparse graph `A` を置くこと。edge conductance は `G` の可用性で gate し、auxin-like
flux update は capacity を育てる。刺激は (a) `N/F/k` への局所 source、(b) graph node の
production/sink、の二経路として明示する。`E` は `G` だけでなく `A` の reroute・flux
増分を読むので、単なる斑点でなく「履歴をもつ虚菌糸」になる。

ただし auxin は植物のモデルであり、fungal electrophysiology の機構説明ではない。
canalisation 自身も canalisation hypothesis を contested と注記する。ここでの採用根拠は
生物同一性でなく、**local feedback から経路記憶を得る設計的有用性**である。

必要改造：

1. page-scoped DOM geometry を外し、`FieldSpec {width,height,seed,regions,clock}` と
   snapshot/replay API にする。parameter texture と state texture は state authority とする。
2. `G` の numeric clock を 1 Hz logical clock と分離。GPU は adaptive substep しても
   output sample 数を変えない。CPU/GPU は同じ immutable parameter table を読む。
3. `A` を別 state として実装。node/edge id、capacity、flux、age を serialise し、
   Gray–Scott shader に「線」を描かせない。`A` の topology 更新は頻度と hysteresis を持つ。
4. `E` の envelope scheduler、種 profile、ADC ingest、CSV/SQLite event log、calibration
   report を加える。mV は UI palette でなく typed quantity とする。
5. `field / graph / signal / instrument` view を同じ snapshot の純粋 observer にする。
   view・LLM narrative・actuator は state を書かない。刺激 command のみ event log 経由で書く。
6. test は deterministic replay、range/units、clock、GPU readback tolerance、topology
   conservation、view digest を分ける。数式更新の失敗を描画の成功で隠さない。

## 4. 実装費用：段階別の現実的見積

前提：経験ある browser/WebGL engineer 1 名、既存の愛無核は未確認、税・機材・実菌実験・
倫理／安全審査を除く。単価は **12–15万円／engineer-day** の発注換算。これは見積であり
見積根拠以外の evidence ではない。

| 段 | 内容 | 工数 | 費用目安 | 出口 |
|---|---|---:|---:|---|
| P0 | source を fork せず extract、seed/replay、logical clock、four views | 4–7 日 | 48–105万円 | 再生可能な G；まだ「菌信号」なし |
| P1 | `A` graph＋`E` envelope、CSV log、property/replay tests | 10–18 日 | 120–270万円 | virtual mycelium simulator；mV は profile-based proxy |
| P2 | 1 Hz ADC ingest、channel/calibration UI、session comparison report | 8–15 日 | 96–225万円 | 実測と同じ時間格子で並べる read path |
| P3 | stimulus command、safety interlock、closed-loop experiment protocol | 12–25 日 | 144–375万円 | read→policy→write の試験基盤；生物的 closed-loop の証明ではない |

P0+P1 は **14–25 日／168–375万円**。P0–P2 は **22–40 日／264–600万円**。
A3 の実演は fungal output→actuator の feed-forward path であり、制御理論上の閉 loop では
ない。P3 を「既に証明済み」と予算化してはならない。24-bit/1 Hz は evidence 上の read
profile だが、具体的機材価格はこの調査では未見積である。

## 5. 代替：自前 field engine 直書きとの比較

| 観点 | Gray–Scott を抽出・改造 | 自前 engine 直 |
|---|---|---|
| 最初の動く substrate | 速い。shader、ping-pong、parameter map、degrade path がある | 遅い。数値核・GPU fallback・observability を新設 |
| 虚菌に必要な A/E | どのみち新設。既存 page は graph・mV・1 Hz log を持たない | 初めから clock/typed units/graph と同設計可能 |
| 真因の明瞭さ | DOM colony、ランダム、visual tuning を剥がさねば混線 | domain state だけで開始でき、headless test が簡単 |
| 維持 | extract が浅ければ原典の演出債を運ぶ | 初期設計責任は重いが dependency/ライセンス境界が明瞭 |
| 適する選択 | 2–4週で「場＋履歴＋信号契約」の PoC を見る | P1 後も長期基盤にする、又は WebGL 以外も同じ replay を使う |

**推奨順**：P0 は Gray–Scott から学びつつ、コードは最小 extract に留める。P1 の graph と
signal contract は UI から独立 package に置く。P1 の replay/distribution gate を通せば
Gray–Scott を残す。通らない、又は state/readback が実装の大半になった時点で、visual
shader を捨てて自前 field engine へ移る。最初から全 page を移植するのも、最初から
生物学モデルと称するのも、どちらも避ける。
